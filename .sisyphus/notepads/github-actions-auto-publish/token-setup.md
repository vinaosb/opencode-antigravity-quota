# VSCE_PAT Setup for Auto-Publish

This document explains how to create a Personal Access Token (PAT) for publishing VS Code extensions and how to add it to this repository's GitHub Actions secrets.

## Create New Token

1. Visit: https://dev.azure.com/_usersSettings/tokens
2. Click "Create new token".
3. Configure the token:
   - Token name: `vinaosb-opencode-quota-monitor-ci`
   - Organization: (leave blank or select your Azure DevOps org)
   - Expiration: 1 year or more (choose a practical rotation period)
   - Scopes: Check ONLY `Marketplace (Manage)` — do NOT grant extra scopes
4. Click "Create".
5. Copy the token immediately. You will NOT be able to view it again.

Important: Do NOT store the token in code, commit history, or CI logs.

## Add Secret to GitHub

1. Visit: https://github.com/vinaosb/opencode-antigravity-quota/settings/secrets/actions
2. Click "New repository secret".
3. Name: `VSCE_PAT`
4. Secret: Paste the token value you copied from Azure DevOps
5. Click "Add secret".

Note: Only a repository admin can add repository secrets. If you need organization-level secrets for use across many repos, use the organization secrets area.

## Verification

After adding the secret:

- Push a trivial commit to the branch the publish workflow listens to (e.g., `master` or `main`).
- Open the repository Actions tab and check the workflow run triggered by the push.
- Confirm the publish job stage reads the `VSCE_PAT` secret and proceeds to the publish step without printing the secret.
- Verify a new extension version is published to the Visual Studio Marketplace (or check workflow logs for successful publish step).

Troubleshooting tips:
- If the workflow fails with authentication errors, double-check the secret name is exactly `VSCE_PAT` and the token has `Marketplace (Manage)` scope.
- Ensure the workflow isn't running in a forked PR context where secrets are unavailable.

## Token Rotation Procedure

Rotate tokens at least annually or immediately after suspected compromise:

1. Create a new PAT following the steps in "Create New Token".
2. Update the `VSCE_PAT` secret in GitHub with the new value (Edit secret -> replace value -> Save).
3. Trigger a workflow run to verify the new token works.
4. Revoke the old token in Azure DevOps to remove access.

Notes on scope and expiration:
- Grant the minimum required scope: `Marketplace (Manage)`.
- Avoid setting expiration shorter than 1 year unless you have automated rotation tooling.

## Security Notes

- Never print secrets in workflow logs. Use masked GitHub secret inputs and avoid echoing environment variables.
- Do not commit or paste the PAT anywhere in the repository or issue trackers.
- Use scoped accounts and least privilege where possible.
